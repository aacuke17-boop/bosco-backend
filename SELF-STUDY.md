# SELF-STUDY: Шаблони в Django

Репозиторій: `bosco-backend`. Складський застосунок `catalog`.

## Експеримент 1 (урок 1): `<script>alert(1)</script>` у назві товару

Сторінка показала цей рядок як звичайний текст, `alert` не спрацював. У коді сторінки:

```html
<td>&lt;script&gt;alert(1)&lt;/script&gt;</td>
```

Django сам замінює небезпечні символи (`<`, `>`, `&`, лапки) на безпечні сутності, тому браузер не сприймає їх як тег. Через це `|safe` для даних від користувача я не використовую.

## Експеримент 2 (урок 4): `DEBUG = False`

Сторінка відкрилась без стилів, а запит до `/static/catalog/css/style.css` дав 404.

`runserver` віддає статичні файли лише при `DEBUG = True`.

## Експеримент 3 (урок 5): форма без CSRF-токена

Результат: помилка 403 з текстом `CSRF verification failed. Request aborted. Reason given for failure: CSRF token missing.` Товар у базі не створився.

**Чому запит відхилено.** Браузер сам додає cookie до кожного запиту на мій сайт, навіть якщо його відправила чужа сторінка. Тому зловмисний сайт міг би відправити POST від імені користувача. Щоб цьому завадити, Django видає форму з секретним токеном і звіряє його з cookie. Чужий сайт цього токена не бачить і не може підставити, тому запит без токена Django зупиняє ще до виклику view.
